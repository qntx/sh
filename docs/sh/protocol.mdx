title: Protocol
description: The stable sh.qntx.org installer contract — flags, exit codes, receipts, trust model.
---

The contract is additive-only: option names, environment variables, exit
codes and the receipt format never change incompatibly.

| sh option             | PowerShell      | Environment                     | Meaning                                                                                                |
| --------------------- | --------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `--version <x.y.z>`   | `-Version`      | `&lt;TOOL&gt;_VERSION`          | Install that version; default is the locked latest                                                     |
| `--variant <name>`    | `-Variant`      | `&lt;TOOL&gt;_VARIANT`          | Install a declared build variant; default is the standard build                                        |
| `--install-dir <dir>` | `-InstallDir`   | `&lt;TOOL&gt;_INSTALL_DIR`      | Absolute path; default `$XDG_BIN_HOME` when absolute, else `~/.local/bin` (`%USERPROFILE%\.local\bin`) |
| `--no-modify-path`    | `-NoModifyPath` | `&lt;TOOL&gt;_NO_MODIFY_PATH=1` | Do not edit PATH                                                                                       |
| `--force`             | `-Force`        | —                               | Reinstall even when up to date                                                                         |
| `--check`             | `-Check`        | —                               | Print the target version, no network, no writes                                                        |
| `--uninstall`         | `-Uninstall`    | —                               | Remove binary, receipt and PATH entry                                                                  |
| `--dry-run`           | `-DryRun`       | —                               | Print planned actions only                                                                             |
| `--quiet`             | `-Quiet`        | —                               | Errors only                                                                                            |
| `--help`              | `-Help`         | —                               | Usage                                                                                                  |

Exit codes: `0` success (including "up to date"), `1` failure, `2` bad
arguments (an undeclared variant name is one, and so is an install
directory given by `--install-dir`/`-InstallDir`/`&lt;TOOL&gt;_INSTALL_DIR`
that is not absolute or contains unsafe characters; a default directory
derived from `XDG_BIN_HOME`/home failing the same checks is `1`), `3`
unsupported platform (including a variant that has no binary for this
platform, and a Linux host whose glibc is older than the measured floor
of every remaining locked build).

## glibc floor

Every `*-linux-gnu` asset in the lock carries a _glibc floor_: the
highest `GLIBC_x.y` version the shipped binary needs, measured by sync
from the binary itself (weak needs included — the same rule as
release-rust's `glibc-floor` check). On a Linux host the installer
detects the host glibc — `getconf GNU_LIBC_VERSION` first, then the first
`ldd --version` line — and skips a gnu candidate whose floor exceeds it;
the musl build stays the preferred candidate as before. When no locked
build can run, the installer exits 3 with a precise message:

```text
error: nosfry 0.4.0 (x86_64-unknown-linux-gnu) needs glibc >= 2.30; this host has glibc 2.28
```

followed by the usual from-source hint. When the host glibc cannot be
determined, the installer warns once and proceeds (`--quiet` suppresses
the warning); the post-extract self-check — `<bin> --version` must exit
0 and report the target version — is the backstop there, exactly as for
a pinned `--version`, which has no floor data at all. A failed
self-check prints the binary's own stderr. None of this adds an option,
environment variable, exit code, or receipt field, and the PowerShell
installer is unaffected.

The PowerShell installer never calls `exit` — that would kill the user's
shell under `irm … | iex`. It writes `error: …` to stderr and sets
`$LASTEXITCODE` instead, so programmatic callers that need a real process
code must propagate it:

```powershell
powershell -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create((irm https://sh.qntx.org/kobe/ps))) -Quiet; exit $LASTEXITCODE"
```

Uninstall removes the binary only when a receipt exists and its
`install_dir` matches the resolved install directory; otherwise it reports
`error: not installed by sh.qntx.org at <dir>` and exits 1 without deleting
anything. The PATH entry (or fish file) is removed only when no other
receipts remain.

Receipts: `$XDG_CONFIG_HOME/qntx/receipts/<tool>.json` when
`XDG_CONFIG_HOME` is absolute, else `~/.config/qntx/receipts/<tool>.json`
on Unix (a relative `XDG_CONFIG_HOME` is ignored per the XDG spec),
`%LOCALAPPDATA%\qntx\receipts\<tool>.json` on Windows:

```json
{ "schema": 1, "tool": "kobe", "version": "6.0.0", "install_dir": "/home/x/.local/bin" }
```

A `variant` field (`"variant": "onion"`) appears only on variant installs;
its absence means the default build. Reinstalling the same version with a
different variant replaces the install.

Trust model: every byte served corresponds to a commit in the public
qntx/sh repository. For the locked latest version the expected SHA-256 comes
from sh.qntx.org (the public git history of the lock) while the archive
comes from GitHub — two sources cross-checked. Repositories with GitHub
immutable releases are recorded in the lock. Verify an asset independently with
`gh release verify-asset v6.0.0 kobe-6.0.0-aarch64-apple-darwin.tar.gz -R qntx/kobe`.
