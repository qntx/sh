# Changelog

All notable changes to this repository will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
`v*.*.*` tags release the `upg` crate; the apps are unversioned
(sh.qntx.org deploys on every push to `main`).

## [Unreleased]

### Added

- The sh.qntx.org installer skips a `*-linux-gnu` build whose measured
  glibc floor exceeds the host's glibc. Sync records the highest
  `GLIBC_x.y` each locked gnu binary needs in `releases.json` (weak
  needs included, the same rule as release-rust's `glibc-floor` check),
  and `install.sh` detects the host glibc via `getconf
  GNU_LIBC_VERSION`, then `ldd --version`, then a single warning when it
  cannot be told (`--quiet` suppresses it) — the self-check stays the
  backstop there, as it already is for pinned `--version` installs,
  which carry no floor data. When no locked build can run, the installer
  exits 3, naming the build, its floor and the host's version —
  `error: nosfry 0.4.0 (x86_64-unknown-linux-gnu) needs glibc >= 2.30; this host has glibc 2.28`
  — followed by the from-source hint. No option, environment variable,
  exit code, or receipt field changes; the PowerShell installer is
  unaffected.

### Fixed

- The post-extract self-check accepted a binary that cannot load
  whenever the archive nests it under `<stem>/` (nosfry's layout):
  the loader error names the extracted path, which contains the
  version, and stderr was matched along with stdout. On a host below
  the floor (RHEL 8's glibc 2.28 vs nosfry's 2.30)
  `curl -fsSL https://sh.qntx.org/nosfry | sh` printed
  `Verified runs 0.4.0`, exited 0, and left a nosfry that fails with
  `GLIBC_2.29`/`GLIBC_2.30 not found`. The self-check now requires
  `--version` to exit 0 as well as report the version.
- A failed `--version` self-check now prints the binary's own stderr.

### Changed

- `releases.json` asset values are objects (`{"sha256": ..., "glibc"?}`)
  instead of bare hash strings; the lock is regenerated by sync, not
  migrated.

## [0.1.1] - 2026-11-24

### Added

- The release-asset contract is pinned, not implied:
  `apps/sh/contract/release-assets.json` is a byte-identical copy of
  qntx/workflows' contract plus a `layout` member, and the supported
  target triples, per-target archive extension, variant pattern, and
  archive layout rule are all derived from it (`src/contract.ts`) — no
  other definition exists. Its examples are the test corpus for the
  asset-name parser, and the installers' candidate triples and archive
  member names are checked against it by test. Documented for tool
  authors in docs/sh/release-assets.mdx.
- The `Sync` workflow deploys sk.qntx.org itself: when a run commits a
  change under `apps/sk/` — or the new `deploy-sk` dispatch input is
  set — a `deploy-sk` job builds `apps/sk` at the pushed commit and runs
  `wrangler deploy` (the exact version `apps/sk/package.json` pins) in
  the `production` GitHub environment, through qntx/workflows' reusable
  `deploy-cloudflare.yml`.
  A missing `CLOUDFLARE_API_TOKEN` environment secret fails the run with
  instructions, and a failing deploy is tracked by a `sync: sk deploy
  failing` issue.
- Installable build variants end to end: the catalog declares them
  (`variants: ["onion"]` for nosfry), sync verifies and locks their
  archives under `variants.<name>` in `releases.json`, and both installers
  take `--variant <name>` / `-Variant` / `<TOOL>_VARIANT` (usage error on
  undeclared names, platform error when the variant has no binary for the
  host). Receipts record `"variant"` on variant installs, so `upg upgrade`
  keeps the installed variant instead of silently reverting to the
  default build.

### Fixed

- An install directory supplied by `--install-dir`/`-InstallDir`/
  `<TOOL>_INSTALL_DIR` that is not absolute or contains unsafe
  characters exited 1 although the documented contract reserves 2 for
  bad arguments; it now exits 2 in both installers. A default directory
  derived from `XDG_BIN_HOME`/home failing the same checks is still an
  environment failure (1).
- `install.sh --uninstall` ignored `--quiet` and always printed progress
  lines; it now honours it (errors only), matching `-Quiet` on Windows.
- `install.sh --dry-run` on a locked install printed the first host
  candidate's asset name even when the lock carries a different target
  (e.g. musl on a glibc host for a tool that ships only gnu); it now
  uses the same first-embedded-candidate selection as the real install.
- A relative `XDG_CONFIG_HOME`/`XDG_BIN_HOME` was used verbatim, putting
  the receipt under the cwd — where upg, which ignores non-absolute XDG
  dirs per the spec, cannot find it. Both now fall back to the defaults
  unless they are absolute.
- Sync parses release assets under the grammar
  `<bin>-<version>[-<variant>]-<target>.<ext>` with `.sha256` (required)
  and `.cdx.json` SBOM (optional, never fetched) sidecars, so nosfry
  v0.4.0 no longer fails as an unrecognized asset; variants the catalog
  does not declare are skipped with a summary line. Unparseable names in
  the `<bin>-<version>-` namespace still fail the sync.
- Sync verification and both installers accept archives that nest the
  binary under a single top-level `<archive-stem>/` directory, matching
  the layout nosfry v0.4.0 ships.
- The `Sync` workflow never ran the `apps/sk` sync although it staged
  `apps/sk/skills.lock.json` and `apps/sk/content` — sk stayed at kobe
  v6.0.0. It now runs after the sh sync, gated by a `source` dispatch
  input (`SYNC_SOURCE`).
- `bun run test` in apps/sk executed a live sync at module load and
  rewrote `skills.lock.json` + `content/`; the sync library now lives in
  `src/source.ts` so tests never reach the entrypoint.

### Changed

- Sync failures are isolated per tool (sh) and per source (sk): a failing
  entry keeps its previous lock state while the rest sync and are
  committed, the run ends red, and each app writes a per-entry status
  JSON (`SYNC_STATUS`). A crash before the per-entry loop still writes
  nothing.
- `Sync` runs hourly (`17 * * * *`) instead of every 15 minutes, and a
  `scripts/track-sync.ts` step keeps a `sync`-labelled GitHub issue per
  failing tool/source — created on first failure, updated by each
  failing run, closed automatically when it syncs again.
- The `Deploy` GitHub workflow was removed and `sync.yml` is
  commit-only: sh.qntx.org is deployed by Cloudflare Workers Builds on
  every push to `main`.
- `packages/github` renamed to `packages/sync` (`@qntx/sync`): GitHub
  client, stable-release selection, lock I/O, plus shared `isRecord` and
  `sha256Hex` helpers now used by both apps.
- Lock model moved out of the catalog module: `apps/sh/src/lock.ts` owns
  the `releases.json` schema/ops and `apps/sk/src/lock.ts` owns the
  `skills.lock.json` schema.
- tsconfig strictness aligned with qntx/spark (`erasableSyntaxOnly`,
  `verbatimModuleSyntax`, `vite.config.ts` in each workspace's program,
  root `tsconfig.json` covering `bump.config.ts`).

### Removed

- Obsolete `oxfmt.config.ts`/`oxlint.config.ts` root files (vite.config.ts
  owns format/lint) and duplicated semver/JSON/hash helpers in the apps.

## [0.1.0] - 2026-10-24

First tagged state of the repository.

### Added

- `apps/sh` — [sh.qntx.org](https://sh.qntx.org): a static, build-time
  rendered installer service for QuantX CLIs (`kobe`, `nosfry`). POSIX sh
  and PowerShell 5.1+/7 installers from `catalog.json` + the sync-locked
  `releases.json`; deterministic `bun run build` into `dist/`; exit codes
  0/1/2/3; per-tool JSON receipts; archive + binary SHA-256 verification.
- `apps/sk` — [sk.qntx.org](https://sk.qntx.org): a static agent-skills
  discovery service serving hash-locked `SKILL.md` files synced from
  source repos (`qntx/kobe`), with a
  `/.well-known/agent-skills/index.json` discovery index.
- `crates/upg` — `upg` 0.1.0: the shared `upgrade` subcommand crate for
  QuantX CLIs; re-runs the official sh.qntx.org installer, detects
  script-/cargo-/unmanaged installs, and reports `Report`/`Action`
  outcomes.
- `packages/sync` — `@qntx/github`: the shared GitHub REST client,
  `vX.Y.Z` stable-release selection, and deterministic lock-file
  serialization used by the sync tasks.

### Changed

- The repository is a Vite+ (vp) monorepo (`apps/`, `packages/`,
  `crates/`); `SYNC_TOOL=""` and `SYNC_SOURCE=""` mean "all".

### Removed

- The `bux` tool and the `installer: "repo"` catalog mode; the catalog is
  `kobe` + `nosfry`.
